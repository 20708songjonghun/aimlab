에임랩(Aim Lab)의 핵심 재미 요소인 **반응 속도, 조준 정밀도, 순발력 측정**을 웹 환경에 맞춰 가볍고 직관적으로 구현하기 위한 웹기반 에임 트레이너 게임 PRD(제품 요구사항 문서)입니다.

# [PRD] 웹 기반 2D 에임 트레이너 (가제: Aim Lab Web)

## 1. 프로젝트 개요

* **목적**: 별도의 설치 없이 브라우저에서 즉시 실행 가능한 가벼운 2D 에임 연습 및 측정 웹 애플리케이션 개발
* **타겟 유저**: FPS 게임(발로란트, 오버워치, 배틀그라운드 등)을 즐기며 에임 연습 및 손풀기가 필요한 유저
* **플랫폼**: Desktop Web Browser (Chrome, Edge, Safari 등 / 마우스 입력 필수)

---

## 2. 주요 기능 요구사항

### 2.1. 핵심 플레이 모드 (3종)

1. **Gridshot (그리드샷 - 정밀도 & 반응속도)**
* 화면 중앙 영역에 고정된 3개의 타깃 생성
* 타깃 1개를 파괴하면 새로운 위치에 1개가 즉시 생성 (항상 3개 유지)
* 제한 시간: 60초


2. **Tracking (트래킹 - 지속 조준)**
* 화면 내에서 일정 속도와 패턴(혹은 불규칙 패턴)으로 움직이는 1개의 타깃 생성
* 타깃 위에 마우스 커서를 올리고 있는 시간(조준 유지 시간)만큼 점수 누적
* 제한 시간: 45초


3. **Spidershot (스파이더샷 - 이동 조준)**
* 항상 화면 중앙에서 시작하여, 타깃을 파괴할 때마다 외곽 임의의 장소에 타깃 1개 생성
* 외곽 타깃을 파괴하면 다시 중앙에 타깃 생성 (중앙 ↔ 외곽 반복)
* 제한 시간: 60초



---

### 2.2. 게임 플레이 메카닉

* **포인터 락 (Pointer Lock API)**: 게임 시작 시 마우스 커서를 브라우저에 고정하고 감도(Sensitivity)를 설정할 수 있도록 처리
* **타깃 메카닉**:
* 타깃 형태: 원형 (원 면적 클릭 시 히트 판정)
* 히트 애니메이션: 파괴 시 즉시 사라지거나 작은 파티클 효과 발생
* 빗나감(Miss) 판정: 타깃 외의 빈 화면 클릭 시 정확도 감점 처리



---

### 2.3. 환경 설정 (Settings)

* **마우스 감도 설정**: Sliders 및 수치 입력 (DPI 반영용 렌더링 스케일 조정)
* **타깃 크기 / 색상**: 타깃 크기(소/중/대), 색상 변경(노랑, 빨강, 시안 등)
* **사운드 효과**: 히트 사운드, 미스 사운드, 배경음 On/Off 및 부피 조절

---

### 2.4. 대시보드 및 결과 창 (Analytics)

게임 종료 후 결과 화면에 다음 데이터 출력:

* **Final Score (최종 점수)**: 파괴 수 × 정확도 계산식 반영
* **Accuracy (정확도 %)**: $\frac{\text{명중 횟수}}{\text{총 클릭 횟수}} \times 100$
* **Reaction Time (평균 반응 속도 ms)**: 타깃 생성 후 파괴까지 걸린 평균 시간
* **Hits / Misses**: 총 명중 횟수 및 빗나간 횟수
* **재시도 / 모드 선택 버튼**

## 3. 기술 스택 제안 (Tech Stack)

| 구분 | 추천 기술 | 비고 |
| --- | --- | --- |
| **Core Framework** | **HTML5 Canvas** + Vanilla JS 또는 **React / Vue** | 빠른 프레임 렌더링을 위해 Canvas API 필수 사용 |
| **Game Engine (선택)** | **Phaser.js** 또는 **Pixi.js** | 2D 퍼포먼스 최적화 및 파티클/사운드 관리가 쉬움 |
| **Styling** | Tailwind CSS / CSS Modules | UI 씬(메뉴, 결과 창, 설정) 구성용 |
| **Data Storage** | LocalStorage | 최고 기록(High Score) 및 사용자 설정 저장 |

---

## 4. 와이어프레임 & UX 흐름

1. **메인 화면 (Main Menu):** 게임 진입 시.
* 모드 선택 카운터 (Gridshot / Tracking / Spidershot)
* 설정(Settings) 버튼
* 최고 기록(High Scores) 표시


2. **게임 시작 전 (Ready Phase):**
* 카운트다운 (3, 2, 1)
* 화면 클릭 시 마우스 커서 감금(Pointer Lock) 실행


3. **게임 진행 (In-Game Phase):**
* 상단 HUD: 남은 시간, 현재 점수, 정확도
* 중앙 영역: 타깃 생성 및 마우스 트래킹 렌더링


4. **결과 화면 (Result Phase):**
* 최종 점수, 정확도(%), 평균 반응속도(ms) 통계 카드 출력
* `Retry` 또는 `Main Menu` 이동 버튼


---

## 5. 단계별 개발 로드맵 (Roadmap)

1. **Phase 1 (MVP)**: HTML Canvas 기반 Gridshot 모드 구현 + 점수/정확도 계산 + 단순 사운드 효과
2. **Phase 2 (기능 확장)**: Pointer Lock 감도 구현, Tracking / Spidershot 모드 추가
3. **Phase 3 (UX/UI)**: 메뉴 시스템, 결과 통계 대시보드 UI 디자인, LocalStorage 데이터 저장
4. **Phase 4 (폴리싱)**: 사운드 믹싱, 파티클 이펙트, 타깃 색상/크기 커스텀 기능
